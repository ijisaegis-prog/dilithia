# Gate 1 Neutral Profile Matrix

These are experimental branches, not defaults, rankings, or recommendations.
Each selected combination must receive its own identity and both candidates.

| Axis | Neutral branches |
|---|---|
| Owner participation | required; not assumed |
| Current acceptance | legacy accepted; legacy rejected; coexistence |
| Migration condition | planned deprecation; distinguishable compromise; catastrophic distinguishability; catastrophic indistinguishability |
| Dormant asset/state | remains current under legacy profile; non-current but historically interpretable; treatment unresolved |
| Historical validation | supported under identified retired version; unsupported; policy unresolved |
| Retrofit | available with exact pre-existing independent information; unavailable; existence unproven |
| Recovery claim | no claim; profile-limited claim requiring evidence; explicit impossibility boundary |
| Authority graph | one relation; several relations; topology unresolved |
| Coverage | grouped; ungrouped; mapping-dependent symmetric branches |
| Evidence validity | valid; malformed; well-formed invalid; scope/domain/version mismatch |
| Protocol/crypto versions | single opaque version; mixed opaque versions; retired/current coexistence |
| Outcome | success; rejection; accepted-unsuccessful only if separately defined by owner |
| History | current authoritative; reverted then reevaluated; historical-only |

Cross-product execution is not authorized merely by this matrix. In particular,
current acceptance, recovery guarantee, authority, version meaning, and any
accepted-unsuccessful consequence remain protected. Candidate-specific
capabilities must be represented by symmetric explicit branches, never silently
granted to one mapping.
