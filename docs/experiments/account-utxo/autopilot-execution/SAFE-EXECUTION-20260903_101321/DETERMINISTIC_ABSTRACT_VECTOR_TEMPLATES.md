# Candidate-Neutral Deterministic Abstract Vector Templates

> **TEMPLATES ONLY — NOT EXECUTED VECTORS OR EVIDENCE.** Determinism here means
> the structural expected relation follows from explicitly supplied symbolic
> inputs. No candidate behavior, mechanism, numeric constant, or protected
> semantic profile is supplied.

Every vector inherits the provenance/profile envelope and mirrored candidate
slots in `NEUTRAL_PAIRED_EVIDENCE_RECORD_SCHEMA.md`.

## Common vector form

`VECTOR_ID` + `GATE` + `SHARED_PRIOR` + `SHARED_INPUT` + `OUTCOME_CLASS` +
`EXPECTED_EXTERNAL_RELATION` + `UNCHANGED_FACTS` + `ROLLBACK_PRIOR` +
`HISTORY_CONTEXT` + `REORG_PROFILE_BRANCH` + `ACCOUNT_SLOT` + `UTXO_SLOT` +
`PROFILE_SET` + `PROVENANCE`.

An expected relation is an oracle specification, not an observed result.

## Structural oracle limits

The rejection templates structurally require the phrase
`ZERO_CANONICAL_EFFECT`. Reorganization templates require an explicit compatible
profile branch while leaving the prior state, rollback relation, expected
result, and any reapplication semantics unresolved protected decisions. A lint
can confirm only that the neutral fields exist. It cannot establish or choose
how an implementation reorganizes, rolls back, restores, or reexecutes.
